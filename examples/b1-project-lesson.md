# B1 familiar software project — short illustration

Topic: `DE-B1-10 — Explaining a software project`. Budget: 20 minutes. Goal: a non-specialist understands who a fictional app is for, what it does and the learner's contribution. Prerequisites are checked from files; technical expertise is not the language target.

Start with one question: “Wem hilft deine Anwendung?” Wait. After the response, ask what a person can do with it. Later ask what the learner built and what comes next. These are separate turns, not a questionnaire or an architecture review.

Suppose the learner says: “Die App hilft Leute, Termine planen.” After they finish, show one main correction: “Die App hilft Leuten, Termine zu planen.” Rule: “helfen требует Dativ; действие здесь оформляется через zu + Infinitiv.” Invite a new example using a different user group. Do not require specialist vocabulary if simple words convey the idea.

Use a clear short audio explanation of another familiar tool and check users, function and limitation. If audio cannot be assessed, mark the gap and continue with an explicitly written alternative. Then ask for a fresh two-minute explanation with the model removed and one unprepared follow-up.

A final two-line message to a fictional colleague practises written transfer. Homework: prepare three keywords, then explain the project without reading a full script. Save only actually observed evidence; no B1 claim follows from this one topic.

For the later KI topic, the scenario supplies a concrete limitation such as occasional incorrect labels. The learner practises expressing the need to check outputs; they are not graded on technical AI safety expertise.
