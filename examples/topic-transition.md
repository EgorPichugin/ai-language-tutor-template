# Topic completion and the next chat

Fictional walkthroughs of the current instructions. No real task is created by reading or rehearsing these examples. Client IDs/links must come from an actual creation result and are never invented here.

## A topic is complete

Assume the learner previously requested separate chats in this same local folder. The current topic is DE-A1-01. Its full final task succeeds, with observed spoken output and verified listening meeting the rubric. The tutor saves the evidence, sets usable, schedules later retrieval, updates the next focus and verifies the files. No checkpoint is due in this scenario.

The next ready topic is DE-A1-02. The tutor checks for an existing destination for this course, records a creating entry in PLAN if needed, and uses a real available tool to prepare one new local task. It saves the returned identifier and shows the client-provided destination. Only then can the closing message say:

> Тема завершена — можно переходить дальше. Вы представились и задали встречный вопрос без подсказки. Прогресс сохранён; короткое повторение будет позже. Следующая тема: DE-A1-02 — Personal details. Чат подготовлен — откройте его и напишите «Начнём».

Include the small homework assignment if one was given. This message closes the current lesson; no further practice questions follow it automatically.

The destination receives a short preparation-only prompt. It reads the required files, names the goal, and waits for the learner. It does not create DE-A1-03, invent learner answers, record a new session, or edit progress while the parent finalizes the registry. On “Начнём” it rereads current state, checks for pending saves or newly due actions, then starts one task. The learner never needs to return to a management chat.

## More work is needed

The final exchange still needs supplied wording. The tutor saves learning (or unstable if its regression criteria apply), records the weak skill and says:

> Занятие закончено. Тему продолжаем в этом чате: пока нужна подсказка для встречного вопроса. Прогресс сохранён. В следующий раз напишите «Начнём» здесь.

No duplicate chat is created for a second session on the same theme. Finishing the time budget is not passing the topic, and the tutor does not prolong the session endlessly to force a pass.

## Text practice succeeds without audio

The written version of the task succeeds independently, but neither listening nor spoken output can be observed. Save the written evidence, retain learning and one modality-gap queue item. The closing message says the oral part is still unassessed. PLAN can select another ready topic and prepare its chat, while clearly stating that progression carries an open gap; do not announce full topic completion.

## Creation is unavailable or interrupted

- No creation tool or same-folder support: keep the saved lesson and give the exact title `DE-A1-02 — Personal details` plus `Start topic DE-A1-02`. Do not claim a chat exists.
- Known existing destination: reuse it, verify the course/location and show the ordinary start command; do not create another.
- Creation accepted but not ready: keep creating with the returned setup identifier, check status using actual client support and report preparation in progress. Do not use a setup identifier as a final task ID.
- Result uncertain after interruption: keep unknown, look up the existing task before any retry. If lookup is unavailable, report uncertainty and ask the learner to check the shown title; do not blindly duplicate it.
- Progress save pending: finish recovery before any creation. Learning evidence must be available to the destination.
- Learner says “Stop for today, don't prepare the next chat”: save and close only; next-topic preparation waits for a later request.
- Finishing a lesson makes a checkpoint due: prepare the checkpoint action in a suitable existing chat; do not skip it just to create a new theme.
- B1 route ends: report completion and remaining gaps/reviews. Do not invent a B2 destination.

For token use, the destination receives the target/mode and file references, not the full previous conversation. Targeted reads avoid unrelated history where file tools allow it. This is a context-management design, not a measured savings claim.
