# Clean state templates

These nine files are deliberately unfilled. “Unknown”, “none” and header-only tables mean no learner evidence yet, not unfinished project work. Setup copies them to `courses/current/`, fills PROFILE/PLAN and the route index in TOPICS, and leaves unused evidence tables empty.

| Template | Contents |
| --- | --- |
| [PROFILE.md](PROFILE.md) | Setup answers and preferences |
| [PLAN.md](PLAN.md) | Personalized A1–B1 route and next focus |
| [TOPICS.md](TOPICS.md) | Topic statuses and thematic chat titles |
| [ERRORS.md](ERRORS.md) | Recurring error patterns |
| [PHRASES.md](PHRASES.md) | Active chunks |
| [REVIEW_QUEUE.md](REVIEW_QUEUE.md) | Due reviews and evidence triggers |
| [LOG.md](LOG.md) | Sessions and save recovery |
| [ASSESSMENTS.md](ASSESSMENTS.md) | Diagnostic and checkpoint evidence |
| [HOMEWORK.md](HOMEWORK.md) | Current practice assignment |

Relative references to INSTRUCTIONS.md use the destination layout `courses/current/`. The same two-level relative path also resolves from this template folder. The fictional demo rewrites links for its own layout.

Read the [file ownership rules](../../INSTRUCTIONS.md) before editing the format. Keep the public templates free of learner data. The agent fills them; the learner does not need to edit tables manually.
